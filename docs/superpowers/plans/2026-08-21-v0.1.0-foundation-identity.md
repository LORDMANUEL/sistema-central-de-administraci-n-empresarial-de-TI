# v0.1.0 Foundation + Identity Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable repository foundation and a complete Identity Service baseline that can bootstrap the first administrator, authenticate, refresh sessions, authorize roles and manage users.

**Architecture:** `identity-service` is an independently deployable FastAPI service with SQLAlchemy-owned persistence and versioned API contracts. Tests use SQLite fixtures while deployment uses PostgreSQL through `DATABASE_URL`; no other service writes Identity tables.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x, Argon2, PyJWT, pytest, Docker/Compose, PostgreSQL 16.

**Spec:** `docs/superpowers/specs/2026-08-21-it-guardian-platform-design.md`

## Global Constraints
- Microservices from v0.1.0; no cross-service database writes.
- Python service target is 3.12.
- All behavior changes follow TDD: failing test must be observed before production implementation.
- API is versioned under `/api/v1`.
- Passwords are Argon2 hashes and are never logged or returned.
- Access and refresh JWTs have distinct token types.
- Disabled users cannot log in or refresh.
- Production secrets come from environment variables.
- Service includes live/readiness checks, Dockerfile, tests and documentation before DONE.
