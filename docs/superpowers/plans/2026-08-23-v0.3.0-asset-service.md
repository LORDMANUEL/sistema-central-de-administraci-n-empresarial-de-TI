# v0.3.0 Asset Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar un Asset Service independiente que administre el modelo canónico de activos de IT Guardian, respete tenancy, publique eventos confiables y pueda incorporarse al stack Docker existente.

**Architecture:** FastAPI/Python 3.12 con PostgreSQL propio (`guardian_asset`), validación de access tokens Ed25519 mediante JWKS de Identity, referencias opacas a tenant/site/department sin escribir la BD de Tenant, y transactional outbox hacia NATS JetStream. El servicio expone únicamente su API y no llama a múltiples motores externos para construir vistas.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16, Alembic, PyJWT/cryptography, NATS JetStream, Prometheus, Docker Compose, pytest.

**Spec:** `MASTER.md` y `ROADMAP.md`

## Global Constraints

- Base de datos independiente por dominio.
- JWT privado solo en Identity; Asset consume JWKS público.
- API versionada bajo `/api/v1`.
- Dockerfile no-root.
- Eventos confiables con transactional outbox y `event_id` idempotente.
- Ningún endpoint vacío o mock se considera producción.
- TDD: cada comportamiento nace de una prueba que falla antes de implementar.
